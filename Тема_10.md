## Лабораторная работа №1
### Наверняка вы думаете, что декораторы – это какая-то бесполезная вещь, которая вам никогда не пригодится, но тут вдруг на паре по математике преподаватель просит всех посчитать число Фибоначчи для 100. Кто-то будет считать вручную (так точно не нужно), кто-то посчитает на калькуляторе, а кто-то подумает, что он самый крутой и напишет рекурсивную программу на Python и немного огорчится, потому что данная программа будет достаточно долго считаться, если ее просто так запускать. Но именно тут к вам на помощь приходят декораторы, например @lru_cache (он предназначен для решения задач динамическим программированием, если простыми словами, то этот декоратор запоминает промежуточные результаты и при рекурсивном вызове функции программа не будет считать одни и те же значения, а просто “возьмёт их из этого декоратора”). Вам нужно написать программу, которая будет считать числа Фибоначчи для 100 и запустить ее без этого декоратора и с ним, посмотреть на разницу во времени решения поставленной задачи.
P.S. при запуске без декоратора можете долго не ждать, для наглядности хватит 10 секунд ожидания.

```python

from functools import lru_cache

@lru_cache(None)
def fibonacci(n):
    if n == 0:
        return 0
    elif n == 1:
        return 1
    return fibonacci(n - 1) + fibonacci(n - 2)

if __name__ == "__main__":
    print(fibonacci(100))
```

```python
import time

def timer(func):
    def wrapper():
        start = time.time()
        func()
        end = time.time()
        print(f"\nВремя выполнения: {end - start:.6f} секунд")
    return wrapper

@timer
def fibonacci():
    fib1 = fib2 = 1
    for i in range(2, 200):
        fib1, fib2 = fib2, fib1 + fib2
        print(fib2, end=' ')

if __name__ == '__main__':
    fibonacci()
```

class EmptyFileError(Exception):
    pass

def read_file(filename):
    try:
        with open(filename, 'r', encoding='utf-8') as f:
            content = f.read().strip()

                raise EmptyFileError("файл пустой")

    except FileNotFoundError:

Придуманное задание:

Создать декоратор-счётчик вызовов, который ведёт отдельную статистику для каждой оборачиваемой функции и выводит, сколько раз была вызвана конкретная функция. Декоратор реализован как класс и используется для двух функций приветствия и прощания.

```python
class Counter:
    def __init__(self, func):
        self.func = func
        self.count = 0

    def __call__(self, *args, **kwargs):
        self.count += 1
        print(f"Функция {self.func.__name__} вызвана {self.count} раз(а)")
        return self.func(*args, **kwargs)

@Counter
def greet(name):
    print(f"Привет, {name}!")

@Counter
def farewell(name):
    print(f"До свидания, {name}!")

if __name__ == '__main__':
    greet("Алексей")
    greet("Мария")
    farewell("Алексей")
    greet("Иван")
```

Придуманное задание:

Создать собственное исключение NonPositiveError, которое возникает при попытке выполнить операции с неположительными числами (≤0). Исключение используется в двух разных функциях: при делении и при обработке значений.

```python
class NonPositiveError(Exception):
    def __init__(self, value):
        self.value = value
        super().__init__(f"Число должно быть положительным, получено: {value}")

def divide_by_number(x):
    if x <= 0:
        raise NonPositiveError(x)
    return 100 / x

def process_value(val):
    if val <= 0:
        raise NonPositiveError(val)
    print(f"Значение {val} успешно обработано")

if __name__ == '__main__':
    try:
        print(divide_by_number(10))
        print(divide_by_number(-5))
    except NonPositiveError as e:
        print("Ошибка:", e)

    try:
        process_value(25)
        process_value(0)
    except NonPositiveError as e:
        print("Ошибка:", e)
```

## Общие выводы по теме
Декораторы и исключения — это два фундаментальных механизма Python, которые значительно повышают качество, читаемость и надёжность кода.
Декораторы позволяют элегантно расширять или изменять поведение функций и методов, не затрагивая их исходный код, что избавляет от дублирования и делает архитектуру программы более чистой и гибкой.
Исключения, в свою очередь, обеспечивают контролируемую и предсказуемую обработку ошибочных ситуаций: программа не «падает» внезапно, а корректно реагирует на проблемы, логирует их и продолжает работу там, где это возможно. Возможность создавать собственные классы исключений даёт точную семантику ошибок, упрощает отладку и делает сообщения об ошибках понятными даже для сторонних разработчиков.
В совокупности эти инструменты превращают обычный код в профессиональный, устойчивый к сбоям и легко поддерживаемый продукт.
